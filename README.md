# GophKeeper
Менеджер паролей

GophKeeper представляет собой клиент-серверную систему, позволяющую пользователю надёжно и безопасно хранить логины, пароли, бинарные данные и прочую приватную информацию.

## Шифрование сейфа(заметки, краты, файлы)

Шифрование **симметричное** (AES-256-GCM). Один и тот же ключ шифрует и расшифровывает данные. Асимметрия (RSA/ECC) не используется: один владелец открывает свои данные своим паролем, сервер в расшифровке не участвует.

Последовательность действий:

1. **Войти в аккаунт** (логин/пароль) — сервер проверяет, что вы это вы.
2. **Открыть сейф** (заметки, карты, файлы) — сервер этого не делает. Он видит только зашифрованный текст.

Пароль учётки и ключ шифрования сейфа связаны на клиенте. Сервер хранит только «обёртки», не сами ключи.

### Параметры регистрации (`RegisterReq`)

| Поле            | Секрет?        | Роль                                                                                                                                                                                                                                                    |
|-----------------|----------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `kdf_salt`      | нет            | Соль Argon2id — случайная «примесь» к паролю, чтобы ключ был уникальным у каждого пользователя                                                                                                                                                          |
| `protected_key` | да (но закрыт) | Ключ сейфа (VK), запечатанный ключом из пароля (KEK)                                                                                                                                                                                                    |
| `key_hash`      | нет*           | Отпечаток VK (`SHA-256`) — проверка, что сейф открылся правильно. после разворачивания VK клиент считает отпечаток и сравнивает с сохранённым. Совпало — пароль верный для сейфа. Это не проверка логина на сервере; сервер хэш только хранит и отдаёт. |

\*По `key_hash` нельзя восстановить ключ; это контрольная сумма, не пароль.

### Параметры Argon2id (`kdf_params`)

Одной соли мало: из пароля ключ получается функцией **KDF** (key derivation function) — у нас Argon2id. Ей нужно сказать **как именно** месить пароль: сколько памяти съесть, сколько раундов сделать, сколько потоков использовать.

`kdf_params` — публичный «рецепт». Его можно хранить на сервере и отдавать при логине. Без пароля рецепт бесполезен; без рецепта клиент не сможет заново посчитать тот же KEK и открыть `protected_key`.

Параметры задаёт **сервер** (политика безопасности) и хранит снимок на пользователя. Клиент их не выбирает сам: иначе можно зарегистрироваться с «дырявыми» настройками.

| Поле          | Что это                                   | Зачем                                                                                                               |
|---------------|-------------------------------------------|---------------------------------------------------------------------------------------------------------------------|
| `algorithm`   | Какой алгоритм (`argon2id`)               | Чтобы клиент знал, чем считать KEK. Сейчас только Argon2id.                                                         |
| `memory`      | Сколько оперативной памяти съесть (в KiB) | Чем больше память, тем дороже перебор паролей на GPU/ASIC. Минимум по OWASP — 19456 KiB (~19 MiB).                  |
| `iterations`  | Сколько раз «прогнать» (раунды)           | Чем больше, тем дольше считать один пароль — атакующему тоже. Типично минимум 2.                                    |
| `parallelism` | На сколько частей/потоков делить работу   | Ускоряет расчёт на многоядерном CPU у честного клиента; значение должно совпасть при открытии сейфа.                |
| `version`     | Версия Argon2 (`19` = `0x13`)             | Разные версии чуть по-разному считают. Нужна, чтобы старый клиент открыл сейф тем же способом, что при регистрации. |

Если при регистрации месили с `memory=19456`, а при входе клиент возьмёт другие цифры — получится **другой** KEK, обёртка не откроется. Поэтому `kdf_params` обязательно едут вместе с `kdf_salt` и `protected_key`.

### Последовательность

**Регистрация (на клиенте):**

1. Пользователь вводит логин и пароль.
2. Клиент генерирует `kdf_salt`.
3. Пароль + соль (+ `kdf_params`) → Argon2id → **KEK** (ключ-обёртка).
4. Клиент генерирует случайный **VK** (ключ сейфа).
5. KEK заворачивает VK → **`protected_key`**.
6. Считается **`key_hash`** от VK.
7. На сервер уходят: логин, пароль (для учётки), `kdf_salt`, `protected_key`, `key_hash`.

Сервер хеширует пароль для входа и сохраняет соль с обёртками. **KEK и VK не знает.**

**Вход:**

1. Сервер проверяет логин/пароль и отдаёт JWT, `kdf_salt`, `kdf_params`, `protected_key`, `key_hash`.
2. Клиент: пароль + соль → KEK → разворачивает VK → сверяет `key_hash`.
3. Дальше VK шифрует и расшифровывает заметки, карты и файлы. В API уходит только зашифрованный текст.

**Сохранение записи:** открытый текст → шифрование VK → на сервер только зашифрованный текст. Сервер прочитать его не может.
