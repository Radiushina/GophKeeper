# Dev TLS certificates

## Зачем это нужно

gRPC между клиентом и сервером идёт по сети. Без TLS данные передаются **в открытом виде** (plaintext): можно перехватить JWT-токен и служебные сообщения.

TLS — это «закрытый конверт» поверх соединения:
1. клиент проверяет, что говорит именно наш сервер, а не подмена;
2. дальше весь трафик шифруется.

Для локальной разработки мы сами себе выдаём сертификаты (**self-signed**). Браузеры их «из коробки» не знают — поэтому клиенту нужно явно сказать, какому удостоверяющему центру (CA) доверять.

## Аналогия

| Файл | Простыми словами |
|------|------------------|
| `ca.key` + `ca.crt` | ваша «печать» и паспорт печати (Certificate Authority) |
| `server.key` | секретная печать **сервера** — никому не отдавать |
| `server.csr` | заявка: «хочу паспорт на имя localhost» |
| `server.crt` | готовый паспорт сервера, подписанный CA |
| `san.cnf` | доп. имена в паспорте: `localhost` и `127.0.0.1` |

**Как проходит рукопожатие (handshake):**
1. Клиент подключается.
2. Сервер показывает `server.crt`.
3. Клиент смотрит в свой `ca.crt`: «этот паспорт подписан нашей печатью?» Если да — доверяет.
4. Стороны договариваются о шифровании. Дальше трафик уже не plaintext.

Кто что держит:
- **сервер** — `server.crt` + `server.key` (показать паспорт и доказать, что он его владелец);
- **клиент** — `ca.crt` (проверить паспорт сервера).

`ca.key` нужен только чтобы **выпускать** сертификаты. В рантайме клиенту и серверу он не нужен.

## Как сгенерировать

Из корня репозитория:

```bash
make certs
```

Это по очереди:
1. `certs-ca` — создаёт CA (`ca.key`, `ca.crt`);
2. `certs-csr` — создаёт ключ сервера и заявку (`server.key`, `server.csr`);
3. `certs-server` — CA подписывает заявку → `server.crt` (с SAN для localhost / 127.0.0.1).

## Что лежит в `certs/`

| Файл | Назначение | В git |
|------|------------|-------|
| `ca.crt` | CA, которому доверяет клиент | можно коммитить |
| `server.crt` | сертификат сервера | можно коммитить |
| `server.key` | приватный ключ сервера | **нельзя** (в `.gitignore`) |
| `ca.key` | приватный ключ CA | **нельзя** |
| `server.csr`, `ca.srl`, `san.cnf` | служебное при генерации | игнорируется |

Публичный `.crt` — не секрет. Секрет — любой `.key`.

## Куда прописать в конфиге

`config/content.yml` (и те же пути в defaults):

```yaml
server:
  grpc:
    tls:
      cert_file: "certs/server.crt"
      key_file: "certs/server.key"
client:
  grpc:
    tls:
      ca_file: "certs/ca.crt"
      server_name: "localhost"   # имя из сертификата (CN/SAN)
```

`server_name` нужен, если подключаетесь, например, к `127.0.0.1:9091`, а в сертификате указано `localhost`: клиент сверяет имя в паспорте с ожидаемым.
